# Qt Quick 界面迁移计划

后续由 AI 按步骤做。一次只做一个步骤，做完编译并对照 `doc/features.md` 里这一步点到的功能。不要把后面的步骤提前做完，也不要在同一次改动里重写播放接口。

GTK 版在迁移完成前保持能运行。新界面放在 `qt/`，不把 `player.py` 删掉，直到最后一步明确切换启动入口。

## 为什么换

现在的界面用 GTK 的 `TreeView`、系统按钮和 CSS 拼出来，封面、圆角、歌词滚动和页面过渡都受控件限制。Qt Quick 用自己的组件画这些区域，列表虚拟化、歌词滚动和封面圆角是它本来就支持的。播放、登录和歌单接口不换。

不换 Java。Swing 和 JavaFX 在麒麟上的字体、缩放和打包都要另做一套，观感也不会更接近官方客户端。

## 保持不变

- `netease_api.py` 继续负责登录、搜索、歌单、歌词和播放地址。QML 不直接请求网易接口。
- 播放地址仍只允许 `https`，主机是 `music.163.com`、`*.music.163.com` 或 `*.126.net`。本地文件只允许音乐目录里的真实文件。
- Cookie 仍在 `~/.local/share/netease-cloud-music/cookie`，目录 0700，文件 0600。不进仓库，不在日志或状态栏打印。
- 不绕过会员和付费限制。服务端降级的档位要原样显示。
- 不使用官方唱片标志。图标继续用 `debian/render-icon.py` 生成的红底音符。
- 不做 MV、社交动态、云盘、商城、发评论和点赞。
- 主窗口留在 Wayland，才能跟上 UKUI 的 1.75 倍缩放。桌面歌词如果必须用 XWayland 才能去掉标题栏和记住位置，继续单独进程，不把整个播放器切到 X11。

## 目标结构

```text
qt/
  app.py                 # 启动 Qt Quick，挂上 Python 模型
  bridge.py              # 把 netease_api 和播放器暴露成 Qt 属性与信号
  player_backend.py      # GStreamer 播放，状态和进度用信号推出
  playback_cache.py      # 已播放音频的本机缓存，总量不超过 1GB
  qml/
    Main.qml             # 窗口、侧栏、页面栈、播放条
    theme/Theme.qml      # 颜色、字号、圆角、间距
    pages/               # 推荐、列表、歌手、专辑、歌词、评论、下载
    components/          # 封面卡片、歌曲行、播放条、菜单
```

Python 和 QML 的边界：

- QML 只发意图：播放这首、跳到这里、喜欢、下载、打开专辑。
- Python 改状态后发信号。QML 不轮询，不在界面线程请求网络，不在界面线程查询 GStreamer。
- 切歌信号要先把进度、歌词和播放图标改到新歌，再等播放地址。不能等出声后才改界面。

视觉只定这些，不照搬官方布局的像素：

- 浅色底 `#F5F5F7`，红 `#EC4141`，次要文字 `#8E8E93`。
- 侧栏悬停浅蓝，当前项浅红底加红字。
- 封面圆角 8。歌曲行高约 56，封面 36。榜单卡片约 148×78。
- 播放条固定在底部，进度条贴在播放条上沿，铺满窗口宽度。
- 字体用系统中文，不把字号放大到把侧栏撑宽。

## 步骤

每步结束的标志写在「完成」里。没达到就不要开始下一步。

### 0. 搭起空窗口

新建 `qt/`，用 PySide6 或 PyQt6 打开一个 1080×680 的无业务窗口。记住位置和大小，限制最小 860×560，并不超过当前屏幕工作区。

完成：`python3 qt/app.py` 能打开和关闭。现有 `./netease-music` 仍走 GTK，不受影响。Debian 依赖里还没改。

### 1. 接上数据和播放后端

`bridge.py` 调用现有 `netease_api.py`。`player_backend.py` 用 GStreamer，提供播放、暂停、跳转、时长、位置和结束信号。位置查询放在播放线程，界面只收信号。

完成：不画完整界面，也能从 Python 播放一首给定地址、暂停、跳转。切歌时位置信号先归零，再从新歌开始。地址校验和现在一样。

### 2. 壳子

`Main.qml` 画出顶栏、侧栏、内容区和底栏的空位。顶栏放搜索框和账号按钮。侧栏先放固定入口，不加载歌单封面。页面用 `StackView`，返回栈和现在的页面历史一致。

完成：窗口缩放时底栏不动，内容区自己滚动。侧栏悬停色和当前项颜色符合上面的视觉约定。

### 3. 播放条

底栏实现封面、歌名、歌手、喜欢、评论、收藏、上一首、播放/暂停、下一首、进度条、时间、播放模式、音质、音量、播放列表按钮、桌面歌词按钮。

进度条可点击和拖动。暂停和未开播时点击停在目标位置。切歌立刻把进度、时间和图标改到新歌。播放图标 20 像素，深色，不使用会变成白色的主题符号。

完成：用本地文件或一条允许的播放地址，能完成播放、暂停、拖动、切歌。界面线程不调用 GStreamer 查询。

### 4. 推荐首页

推荐歌单和六个榜单卡片。封面异步加载，先占位，回来再替换。榜单封面不再叠字。卡片约 148×78。首页显示出来就能点，不用先切走再回来。

完成：点击歌单或榜单进入下一步的列表页。封面缓存仍用现在的用户数据目录。

### 5. 歌曲列表

用虚拟化列表，不要一次性创建全部行。列和现在一样：序号、封面、歌名、VIP、歌手、专辑、时长。只给可见行附近加载封面。

双击播放并替换播放列表。点击歌手、专辑进入对应页。右键菜单包含下一首播放、喜欢、下载、评论、收藏到歌单，以及有权限时的移除。

歌单按页追加，不清空已经显示的第一页。「我喜欢的音乐」仍按红心时间从新到旧。

完成：打开一个长歌单，窗口高度不变，滚动流畅，右键菜单和双击播放可用。

### 6. 歌手页和专辑页

歌手页包含头像、名字、别名、计数、简介、专辑芯片和热门歌曲。专辑页包含封面、名称、歌手、简介和曲目，曲目在页内滚动。

多歌手时从播放条弹出选择。两页的歌曲行复用第 5 步的行和右键菜单。

完成：从列表进歌手，再进专辑，返回顺序和 GTK 版一致。

### 7. 歌词页和桌面歌词

歌词页居中，当前句放大，点击一行跳转，翻译跟在原文下面。高亮不提前半拍。

桌面歌词保持无边框、任务栏上方居中、可拖动、记住位置和开关状态。悬停浅灰蒙版，淡红关闭按钮，窗口高 64。已唱淡蓝，未唱白色，颜色在歌词进程内按时间前进。退出主程序时关掉歌词窗口。

如果 Qt 在 Wayland 上仍然去不掉标题栏或不能定位，桌面歌词继续用单独的 XWayland 窗口，不把主窗口切到 X11。

完成：主窗口缩放正常。桌面歌词没有标题栏，拖动后重开位置还在，退出音乐时歌词窗口消失。

### 8. 播放缓存

已经出声的歌，在后台把整首存到 `~/.cache/netease-cloud-music/playback/`。下次同一首、同一实际音质直接播这个文件，不再请求播放地址。

和手动下载分开。下载仍进音乐目录的「网易云音乐」，并写入本地索引；缓存不进音乐库，也不在下载管理里出现。手动下载的文件优先于缓存。

规则：

- 只缓存通过现有地址校验的 `https` 音频。本地文件和已经命中缓存的歌不再写一份。
- 文件名只用歌曲 id、实际档位和扩展名，不能从歌名拼出目录。先写临时文件，下完再换正式名。
- 索引只记歌曲 id、实际档位、字节数和最后播放时间。不记 cookie，不记完整播放地址。
- 全部正式缓存文件合计不超过 1GB。写入前和写完后都检查，超出就按最后播放时间删旧文件，直到回到 1GB 以内。正在播放的文件跳过。
- 缓存损坏、扩展名对不上或文件不在缓存目录里，丢掉索引并重新拉流。
- 界面线程不下载、不扫描目录。

完成：同一首歌连播两次，第二次不发播放地址请求。把缓存填过 1GB 后，最久没听的被删掉，总量回到 1GB 以内。正在听的那首还在。

### 9. 账号、评论、下载、FM 和排行

扫码登录和退出。评论只读，分页。下载队列写入音乐目录的「网易云音乐」，文件名不能跳出该目录。私人 FM 播完续一批。听歌排行显示最近一周。

完成：未登录不能喜欢、收藏或下载，并给出和现在一样的提示。登录凭证不出现在界面和日志里。

### 10. 托盘、快捷键和恢复播放

关闭窗口隐藏到托盘，左键打开，右键退出。空格、方向键、Ctrl+F、Esc、Ctrl+Q 和三组全局快捷键保持现在的行为。没有全局快捷键服务时跳过。

启动恢复列表、歌曲、音质、模式和进度，不自动播放。

完成：关掉窗口后音乐继续。重新打开后进度还在，第一次点播放才出声。

### 11. 切换启动入口

`./netease-music` 改为启动 Qt Quick。GTK 的 `player.py` 先留在仓库里，不在这一步删除。桌面歌词和托盘还调用它，所以 GTK、GStreamer 和 AppIndicator 的运行依赖先保留。Debian 依赖增加 Qt Quick 运行库。

完成：菜单入口和源码入口都打开新界面。`doc/features.md` 里的功能点都有对应操作。打包脚本仍生成自己的红底音符，不带官方标志。

## 每步都要检查

- 界面线程没有网络请求，没有 GStreamer 位置查询。
- 播放和下载地址仍经过现有的主机校验。
- 不提交 cookie、登录二维码、`state.json`、桌面歌词位置和窗口位置。
- 不打印 cookie 和完整播放地址。
- 窗口不会因为列表变长而超过屏幕。
- 一步没完成，不开始下一步。第 11 步完成后，源码入口和安装入口都启动 Qt Quick。
